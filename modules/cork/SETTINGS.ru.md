# Настройки cork

[English](SETTINGS.md) · [README](README.ru.md)

У cork нет настроек, которые человеку стоило бы подбирать. Каждое число, по которому он работает,
это постоянная рядом с местом, где она нужна, выбранная по замеру. То, что cork принимает как
`config` (в `createMachine`, через `--config '<json>'` в `cork run` или как
`createApp({ cork: { config } })` в `@bottlify/core`), бывает трёх видов: что передаёт хост, чтобы
встроить cork в себя; переключатели, которые выключают путь или добавляют прибор, пока ищут
ошибку или цену; и рычаги, которые нужны тестам, чтобы быстро дойти до нужного состояния. Ничто из
этого не предназначено для того, чтобы его меняла выпущенная программа.

**Что передаёт хост**

| Настройка | По умолчанию | Что это |
| --- | --- | --- |
| `atomic` | `false` | Инструкции с префиксом `lock` и `xchg` с памятью как атомарные операции wasm. Ядро включает её для процесса, потоки которого работают на нескольких исполнителях над одной памятью. |
| `ordered` | `false` | Вместе с `atomic`: загрузка и запись целого операнда не через esp тоже атомарные, если адрес выровнен. Так сохраняется порядок обычных записей на хосте, который их переставляет (arm64). Выключена, пока её не попросит страница. |
| `trapPort` | нет | Порт ввода-вывода, `out` в который означает вызов хоста. |
| `worker` | включено, где есть `Worker`, если `feed` не `'slice'` | Перевод и компиляция в воркерах трансляции; `false` переводит в вызывающем потоке. |
| `workerUrl` | рядом с рантаймом | Где лежит `translator.worker.js`, если сборщик его переносит. |
| `translators` | 1 | Сколько воркеров рантайм открывает сам; 0, когда их одалживает пул хоста. |
| `arena` | нет | Арена кэша трансляций (`createArena`), общая для всех исполнителей процесса; если её нет, рантайм создаёт свою. |
| `sharedCode`, `doorbell` | нет | Где лежит запись процесса о коде, общем для его исполнителей, и какой исполнитель этот рантайм; слова, в которые звонит воркер трансляции, когда ответил. |
| `awaited` | нет | Ждёт ли другой исполнитель ответа этого: пока ждёт, формирование и поиск останавливаются на следующем регионе. |
| `store`, `bundleId` | нет, `'unknown'` | Где трансляции хранятся между запусками (ядро даёт своё хранилище каждому бандлу в OPFS) и их пространство имён. |
| `cacheVersion` | версия транслятора | Версия выше собственной версии транслятора: любая запись другой версии считается промахом. |
| `feed` | `'frame'` | Когда формируются кандидаты: раз в кадр или после каждого слайса (`'slice'`, для программы, которая ничего не показывает; так делает `createMachine`). |
| `sharedMemory` | `true`, где возможно | Память гостя как `SharedArrayBuffer`, если страница изолирована от других источников; `false` оставляет её частной, и программа работает на одном исполнителе. |
| `cacheBytes` | 256 МиБ | Сколько байт wasm могут занимать модули, в которых лежат работающие регионы; сверх этого отпускаются те, что дольше всех не работали (0: без потолка). Ядро ставит потолок только на пути для iOS, описанном ниже. |
| `crossTailCalls`, `dispatch`, `callDepth` | `true`, `false`, `CallStack.LIMIT` (256) | ХАК до выхода в iOS [WebKit PR #76671](https://github.com/WebKit/WebKit/pull/76671): iOS 27 убивает страницу при хвостовом вызове в другой экземпляр ([WebKit bug 325447](https://bugs.webkit.org/show_bug.cgi?id=325447)) и переполняет стек воркера в 512 КБ, поэтому на iPhone ядро передаёт `crossTailCalls: false`, `dispatch: true` и `callDepth: 64`. |

Помимо `config` ядро принимает `cork.pool`, `cork.poolPerProcess`, `cork.poolWindowMs` и
`cork.poolDriver`, а в `createApp` ещё `quantum` и `executors`: см.
[`docs/core/configuration.md`](../../docs/core/configuration.md#cpu).

**Отладка**

Каждый переключатель выключает путь, чтобы исключить его из подозреваемых, или добавляет прибор;
каждый делает код медленнее или больше. Запуск с `blockProfile` или с исключёнными классами
инструкций (`leaveOut`) не ведёт хранилища трансляций. Некоторые из них служат опорной стороной
дифференциальных проверок.

| Настройка | По умолчанию | Что делает |
| --- | --- | --- |
| `translate` | `true` | `false` всё интерпретирует: с таким запуском сравнивают переведённый. |
| `leaveOut` | `[]` | Классы инструкций (`'x87'`, `'mmx'`, `'sse'`), оставленные интерпретатору. |
| `interpretRange` | нет | `[from, to)`: адреса, оставленные интерпретатору. |
| `wasmInterpreter` | `true` | `false` оставляет только интерпретатор на JavaScript (хост ядра). |
| `precise` | `false` | Флаги исключений x87, сигнальные NaN, антипереполнение, C1 и флаги, которые инструкция оставляет неопределёнными, ведутся так, как их ведёт процессор; включают тесты соответствия и аппаратный корпус. |
| `exactNaN` | `false` | Каждый NaN, который даёт операция с плавающей точкой, получает знак как на x86, а не как на хосте. |
| `checkReads` | не задано | `true` с самого начала проверяет страницы каждого чтения, `false` не закрывает ни одной страницы. Если не задано, чтения заворачиваются в пределы памяти, пока программа впервые не упадёт на закрытой странице, а с этого момента проверяются. |
| `looseStacks` | `true` | `false` проверяет страницы каждой записи через `esp`. |
| `structure` | `true` | `false` отправляет каждый переход назад внутри региона через его диспетчер. |
| `callReturn` | `true` | `false` превращает каждый вызов и возврат из региона в переход через хеш входов. |
| `leafCalls` | `true` | `false` не встраивает в вызывающий регион ни одной листовой функции. |
| `formDepth` | 1 | Сколько уровней встроенных функций могут сохранить собственные прямые вызовы (0: только листовые); 2 и 3 по замерам медленнее. |
| `emptyCalls` | `true` | `false` входит в функцию, которая ничего не делает, вместо того чтобы вернуться из неё прямо в переходе. |
| `linkedCalls` | `true` | `false` отправляет каждый прямой вызов через переход вместо вызова функции из первого слота хеша. |
| `callTargets` | `true` | `false` не собирает выборку косвенных вызовов и не встраивает предсказанные функции. |
| `wideFirst` | `true` | `false` проверяет управление точностью на каждой операции x87 с округлением. |
| `floatSingles` | `true` | `false` округляет каждый результат x87 одинарной точности из double. |
| `x87Shapes` | `true` | `false` проверяет каждое обращение к регистру x87 вместо одной проверки формы стека на входе. |
| `blockProfile`, `blockProfileFrom` | `false`, 0 | Число выполнений каждого блока начиная с заданной секунды, а рядом `mechanisms` (как прошли вызовы, возвраты и переходы) и `forms` (сколько раз выполнилась каждая форма инструкции и сколько байт wasm она дала). |
| `timings` | `false` | Время каждой фазы транслятора. |
| `traceStore` | `false` | Ключи хранилища трансляций: записанные и не найденные. |
| `checkStale` | `false` | Регионы, которые ещё опубликованы, хотя их байты уже формируются иначе. |
| `countTransfers` | `false` | Переходы между регионами через хеш; `transfers` в диагностике есть только с ней. |

**Для тестов**

Рычаги, которые тест ставит, чтобы дойти до нужного состояния за несколько инструкций или сделать
запуск повторяемым. Значение по умолчанию и есть значение продукта.

| Настройка | По умолчанию | Что сдвигает |
| --- | --- | --- |
| `hotThreshold` | 2 | Сколько переходов на адрес нужно, чтобы он стал кандидатом (`createMachine`: 50). |
| `missThreshold` | 64 | Сколько выходов на один адрес нужно, чтобы он стал кандидатом. |
| `maxQueued` | 8192 | Сколько кандидатов может ждать; сверх этого отбрасывается самый холодный. |
| `batchRegions`, `maxBatchRegions` | 32, 256 | Регионов в модуле wasm и наибольшая пачка при длинной очереди. |
| `holdMs` | 4 | Сколько времени потока движка работа транслятора может занять подряд, если нужен воркер (0: пачка формируется и публикуется целиком за один вызов). |
| `inFlightMs` | 10000 | Сколько пачка может пробыть у воркера, прежде чем от неё откажутся. |
| `volatileAfter`, `volatileWindowMs`, `volatileHoldMs` | 8, 100, 2000 | Сколько записей, сбрасывающих код страницы, в пределах окна нужно, чтобы страницу стали интерпретировать, и как долго. |
| `maxRegionBlocks` | 128 | Блоков в самом большом регионе. |
| `leafBytes` | 512 | Байт во встраиваемой листовой функции. |
| `predictAfter`, `callWindow` | 48, 1024 | Сколько выборок косвенного вызова нужно, прежде чем смотреть на его цели, и сколько чтений их хранить. |
| `relinkAfter`, `relinkRegions`, `relinkCold` | 16, 512, 128 | Сколько модулей пачек нужно, прежде чем работающие регионы соберут в крупные (0: никогда), сколько регионов в каждом и сколько в каждом модуле холодных. |
| `mergeAfter` | 2^16 | Сколько переходов между двумя модулями нужно, чтобы их слить (0: никогда). |
| `checkedAfter` | 4 | Сколько неудачных проверок формы стека x87 нужно, чтобы регион сформировали заново без неё. |
| `hashSlots` | 2^20 | Слотов в хеше входов (по 12 байт). |
| `yieldChunk` | 10000 | Сколько инструкций переведённый код выполняет за раз, пока слайс может закончиться раньше (`createMachine`: 2^24). |
| `sliceMs` | 8 | Сколько может длиться слайс интерпретатора. |
| `wasmInterpreterAfter` | 8192 | Сколько работы делает интерпретатор на JavaScript, прежде чем его сменит уровень wasm. |

Некоторые размеры зафиксированы, потому что под них построены переведённый код и заранее
собранный интерпретатор wasm: смещения блока состояния, таблица флагов страниц (байт на страницу
в 4 КиБ), таблица гранул кода и таблица счётчиков горячести интерпретатора wasm.
